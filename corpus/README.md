# Conformance corpus

A fixture lives under `corpus/fixtures/<name>/` and holds one rendering per language: a Go rendering is one `go.txtar` archive holding the target and consumer modules as sections, and a TypeScript rendering is a `ts/` directory. An analyzer loads a rendering and analyzes it exactly as it would a real repository. One expectation file, `expect.json`, sits beside the renderings and names, in a language-neutral form, which findings an analyzer must report and which it must not report, per issue kind and per exemption class. Each rendering's manifest, `fixture.json`, binds every logical name the expectation file uses to a file and a line in that rendering, and declares the build matrix a run derives from the rendering where the rendering has one, which is what an expectation's configuration list is drawn from. A declared gap is a value an analyzer writes into its conformance report for a capability it does not implement; an expectation that is neither answered nor declared fails the analyzer, so a gap is reported rather than omitted. An analyzer commits `conformance.json`, its declared gaps, and its corpus runner writes `conformance-results.json`, both against the schemas in this directory.
