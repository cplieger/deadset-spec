# Conformance corpus

A fixture lives under `corpus/fixtures/<name>/` and holds one rendering per language: a Go rendering is one `go.txtar` archive holding the target and consumer modules as sections, and a TypeScript rendering is a `ts/` directory. An analyzer loads a rendering and analyzes it exactly as it would a real repository. One expectation file, `expect.json`, sits beside the renderings and names, in a language-neutral form, which findings an analyzer must report and which it must not report, per issue kind and per exemption class. In a Go rendering each consumer module requires the target module and carries a `replace` directive naming the target's path relative to the consumer directory, `../target`, so the rendering loads with no network access. Each rendering's manifest, `fixture.json`, binds every logical name the expectation file uses to a file and a line in that rendering, and declares the build matrix a run derives from the rendering where the rendering has one, which is what an expectation's configuration list is drawn from. An expectation may also name the kind of subject its finding is about, drawn from the `symbol.kind` vocabulary of [`../contract/finding.schema.json`](../contract/finding.schema.json); a runner then checks the reported finding's own subject kind against it and reads that schema's rule on the liveness relation from it, so a row naming a part of a declaration expects a finding with no relation and a row naming a declaration expects one. A row that names no subject kind is answered without either check, so the member changes nothing for a fixture that omits it. A declared gap is a value an analyzer writes into its conformance report for a capability it does not implement; an expectation that is neither answered nor declared fails the analyzer, so a gap is reported rather than omitted. An analyzer commits `conformance.json`, its declared gaps, and its corpus runner writes `conformance-results.json`, both against the schemas in this directory.
